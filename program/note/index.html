技術說明：資料如何儲存 (IndexedDB)

筆記存在瀏覽器的 IndexedDB，資料庫 notes-db、物件庫 notes，主鍵為 id，並建立 updated 索引。設定 (主題、字體) 則存在 LocalStorage。

{ id, title, body, folder, tags: [], pinned, created, updated }

輸入後約 500ms 自動儲存 (debounce)；也可按「💾 儲存」或 Ctrl/⌘+S 立即寫入。離開頁面或切換筆記時同樣會即時寫入。資料只在本機，不會上傳。

技術說明：持久化 navigator.storage.persist()

瀏覽器在空間不足時可能清除「盡力而為」(best-effort) 的站點資料。呼叫 navigator.storage.persist() 可申請「持久化」，被批准後不會被自動清除，只有使用者手動清除才會刪除。

Chrome 會依互動程度、是否已安裝 PWA 等自動決定，不一定彈出提示；Firefox 會詢問使用者；Safari 對已加入主畫面的網站較寬鬆。即使批准，仍建議定期匯出 JSON 備份。

技術說明：JSON 匯入 / 匯出

匯出格式為 { app, version, exportedAt, notes: [...] }。匯入時可選「合併」(相同 id 以較新的 updated 為準) 或「取代全部」。匯入時會驗證欄位類型，並移除不合法的資料。亦接受純陣列格式。

技術說明：Service Worker 與離線

sw.js 在安裝時預先快取 index.html、manifest.json 與圖示。之後網頁請求採用「快取優先、背景更新」策略，因此第二次開啟起即使完全離線也能使用。

更新網站時，請修改 sw.js 內的 CACHE 版本號，舊快取便會在啟動時被清除。Service Worker 需要 HTTPS (或 localhost)；GitHub Pages 已符合。

技術說明：PWA 與 manifest.json

可安裝的 PWA 需要：HTTPS、manifest.json (含 name、start_url、display、192/512 圖示)、並註冊 Service Worker。本專案使用相對路徑 (./)，所以放在 GitHub Pages 的子路徑 (如 /repo/) 也能正常運作。

Chrome / Edge 會觸發 beforeinstallprompt 事件，本頁攔截後以自訂橫幅提示；iOS Safari 沒有此事件，需手動：分享 → 加入主畫面。

技術說明：響應式設計與 Markdown

採 CSS Grid：≥1100px 三欄 (側欄 / 列表 / 編輯器，可並排預覽)；700–1099px 兩欄，側欄變抽屜；<700px 單欄，列表與編輯器切換，並有浮動新增按鈕。

內建小型 Markdown 解析器 (無外部依賴)：先轉義所有 HTML 再套用格式，連結只允許 http(s)/mailto，以避免 XSS。支援標題、粗體、斜體、行內/區塊程式碼、引用、清單、核取清單、連結、分隔線。

快捷鍵：Ctrl/⌘+S 立即儲存、Ctrl/⌘+K 搜尋、Alt+N 新增。
